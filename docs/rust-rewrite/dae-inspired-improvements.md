# Linux 运行时：DNS 合并、平滑策略重载与零拷贝

本轮参考 dae 的运行时设计，在既有 Rust Clash/Mihomo 核心中独立实现 DNS 并发查询合并、保持 TCP 的策略重载、Linux TCP splice 转发、透明 UDP 持续收发，以及 TUN 自动路由的归属与崩溃恢复。既有 YAML 和控制器接口继续使用，不增加启用开关。

## DNS 并发查询合并

DNS 入口把同一解析器实例上同时到达的相同请求交给一个上游查询，其余调用共享结果。匹配键保留完整 DNS 请求，包括问题名称大小写、类型、标志和 EDNS 选项；仅事务 ID 不参与匹配。每个响应重新写入原调用的事务 ID。

该机制共享尚未完成的查询，不保存已完成响应，不改变已有 TTL 行为。解析器实例不同的请求不会共享结果，避免 DNS 策略重建后收到前一实例的答案。hosts、fake-IP 等本地回答仍先由权威共享 DNS 状态处理。

最多保留 256 个进行中的键，每个请求最多保留 4096 字节；超过限制的请求走原解析流程。上游失败会传播给等待者，工作线程异常退出也会释放键并唤醒等待者，不会把失败永久缓存。

## 保持连接的策略重载

规则、节点、策略组、provider、模式、日志级别和嗅探设置可以在运行时更新。新配置先完成解析、编译和必要的预热，再发布到当前运行时。规则、注册表和模式的更新与新连接规划使用同一个同步边界，防止匹配到新规则却查找旧节点。

适用条件是监听器、控制器、TUN、eBPF、路由标记、DNS 行为和运行目录保持一致。DNS 编译结果和 TUN 路由集合依赖的数据也参与检查；provider 文件变更会按需要重建网络配置。

符合条件时保留监听 socket、TUN worker、BPF 程序、DNS 分配、已有 TCP 和流量统计。已建立 TCP 继续使用建立时的节点；新连接按新策略选择。UDP 缓存和内核 UDP 流会失效，后续数据重新判定。健康检查和 Smart 后台任务按新配置重新启动，未改变定义的节点保留健康状态。

修改监听地址、网络拓扑或 DNS 行为等设置时仍走原来的重建与回滚流程。这里不承诺该类重载保持已有连接，也不把尚未完成拨号的连接视为已建立 TCP。

## Linux TCP splice

默认 TCP 策略现在会在两端都明确提供纯 TCP 能力时使用 `splice`。能力由流类型显式声明；TLS、代理加密、WebSocket、多路复用及需要拦截读写的统计包装默认不声明该能力。

回放前缀先按正常读写发送，全部发送后才转入 splice，保证嗅探或握手预读的字节不丢失、不重复。双向连接统一设置和恢复 socket 的非阻塞标志，保留 socket 超时与 TCP 半关闭语义；写入背压下可以响应取消。统计按实际写入对端的有效字节更新。

每个方向的管道目标容量为 64 KiB，分配失败或系统不支持时回到有缓冲的转发。管道按连接释放，没有无界的全局管道池。纯 splice 路径不分配用户态复制缓冲；管道使用的内核内存不包含在进程 RSS 中。

这项优化适用于 Linux 的纯 TCP 转发，包括符合条件的 mixed、redir、SOCKS5 等路径。用户态 TUN TCP 协议栈不提供原生 TCP 文件描述符，继续使用既有转发；本轮没有把该协议栈替换成 dae 的内核透明代理入口，也没有增加硬件流量卸载。

## 透明 UDP 会话和持续回包

redir/TPROXY 的 UDP 监听按客户端和目标复用会话，使用有界缓存和独立收包任务。这样 QUIC 为嗅探而缓存的多个数据报发出后，代理关联仍保持有效，后续响应无需等待客户端再发送一个请求。

监听器复用现有 TUN 的 UDP 会话与解码器逻辑；每个监听器最多 256 项，透明 UDP 默认空闲超时 30 秒。关闭监听器会先禁止新建会话，再取消和回收接收任务。策略代次变化后旧接收任务停止，避免回传先前节点的数据。

不支持分离接收或无法创建接收任务时，保留请求/响应处理。该变更不宣称所有入口均采用相同的 UDP 生命周期，也不把会话复用等同于已验证所有协议的 full-cone NAT。

## TUN 自动路由归属和恢复

启用 `tun.auto-route` 时，核心按网络命名空间和路由表取得独占锁，使用协议号 242 标记自己创建的规则和路由。安装前检查冲突；已有外部优先级或相同前缀的路由不会被覆盖。

每个变更先写入原子替换的恢复日志，再执行 `ip`。锁由配置子进程共同持有，避免父进程被强杀后，尚未退出的 `ip` 进程晚于新实例修改路由。下一次同权限启动会回收日志中登记的旧对象，随后安装新配置。

正常退出和启动失败按归属回滚，保留外部规则和路由。日志和锁位于 `/tmp/mihomo-tun-routes-<netns>-<table>.*`；不要为清理本核心而刷新整个路由表或删除整个 TC 配置。

旧版本没有写入这类归属日志，无法据此自动识别旧版本的无标记遗留对象。升级时应正常停止旧核心后替换文件；若旧核心此前被强杀，需要先处理它遗留的规则。
